1) What This Codebase Is

Hugo Extended Docsy Theme SCSS Overrides GitHub Actions GitHub Pages

This is a static website built with Hugo and Docsy. Your custom code mainly lives in layouts/, assets/scss/, and content/.

2) Runtime Model (Live Site Behavior)

  1. Hugo compiles markdown + templates into static files in public/.
  2. GitHub Actions uploads public/ to Pages.
  3. GitHub Pages serves HTML/CSS/JS.
  4. Browser JS handles dark/light mode toggle.

No backend process runs for this site in production.

3) Folder Responsibilities

content/
All pages, docs, blog posts.
layouts/
Template overrides; takes precedence over Docsy defaults.
assets/scss/
Theme variables + global visual overrides.
_vendor/
Vendored modules (Docsy, Bootstrap, Font Awesome).
hugo.yaml
Site config, menu, params, taxonomies, markup settings.
.github/workflows/hugo.yaml
Build and deploy pipeline.

4) Hugo + Docsy Rendering Flow

Hugo resolves templates in this order:

  1. Your layouts/ overrides
  2. Docsy module templates

Key custom overrides:

  • layouts/partials/navbar.html - custom navbar + theme toggle JS
  • layouts/partials/hooks/head-end.html - SEO meta tags
  • layouts/blog/list.html - blog list grouped by year + pagination
  • assets/scss/_styles_project.scss - global dark/light system and UI overrides

5) Content Routing

  • content/_index.md -> / (home)
  • content/docs/_index.md -> /docs/
  • content/docs/architecture.md -> /docs/architecture/
  • content/blog/_index.md -> /blog/

Home page is shortcode-driven using Docsy blocks (cover/lead/section/feature).

6) Theme Toggle Internals

  1. Read localStorage.theme (default dark).
  2. Set data-bs-theme on <html>.
  3. On click, switch dark / light, save state, update icon.

SCSS maps each mode to CSS variables for backgrounds, text, links, navbar, code blocks, TOC, and footer.

7) Markdown, Mermaid, and Highlighting

  • params.mermaid.enable: true
  • markup.goldmark.renderer.unsafe: true (allows raw HTML in markdown)
  • markup.highlight.style: dracula

Mermaid diagrams in docs are rendered as part of the static site and styled by your CSS overrides.

8) CI/CD and Deployment

Workflow: .github/workflows/hugo.yaml

  1. Trigger on push to main.
  2. Install Hugo Extended + Dart Sass.
  3. Run npm ci if lock file exists.
  4. Build with hugo --gc --minify.
  5. Upload public/ artifact.
  6. Deploy using actions/deploy-pages@v4.

9) Custom vs Theme Ownership

Custom-owned (your repo)
  • Home content composition
  • Navbar + theme toggle logic
  • SEO head tags
  • Blog list override
  • Dark/light palette system
Theme-owned (Docsy)
  • Base templates and page shell
  • Most docs/blog layout behavior
  • Shortcode implementations
  • Bootstrap and core theme JS/CSS

10) End-to-End Mental Model

content/*.md + hugo.yaml + layouts overrides + SCSS
                    |
                    v
                Hugo build
                    |
                    v
         static public/ HTML CSS JS
                    |
                    v
        GitHub Actions -> GitHub Pages
                    |
                    v
     Browser loads page + applies saved theme

If you edit content, templates, or SCSS and push to main, this pipeline regenerates and republishes the live site.
